# 给水排水工艺流程图（水厂 / 污水厂）符号与规则规格

> 这份文档是给排水域包的**记法依据**：符号画成什么样、为什么这么画、管线怎么区分介质、
> 工艺校验都查什么，都能在这里对回来源。
> 实现见 `src/water/water_shapes.ts` 与 `src/water/WaterProcessDesigner.ts`，
> 示例页见 `examples/water-editor.html`，回归见 `tests/water/` 与 `e2e/water-editor.spec.ts`。

## 1. 依据的标准

| 标准 | 用途 | 本包怎么用 |
|---|---|---|
| **GB/T 50106-2010《建筑给水排水制图标准》** | 给排水专业的制图图例体系（管道、阀门、仪表等，第 3 章「图例」） | 管道 / 阀门 / 仪表 / 出水口这类通用图例按它的通行画法实现；该标准主要面向建筑给排水，**市政厂站图的画法沿用它建立的图例约定**，再按工艺专业的习惯补充工艺单元画法 |
| **GB 50014《室外排水设计标准》、GB 50013《室外给水设计标准》** | 工艺单元与设计参数体系 | 只取"单元怎么称呼、按什么顺序串联"，**不做水力计算**（计算交给专业水力软件） |
| 工艺专业通行画法 | 格栅、沉砂池、初沉池、生物池、二沉池、浓缩池、脱水机… | 用**可辨识特征**表达（例：格栅＝矩形＋斜栅条；曝气池＝矩形＋曝气盘排列），不照抄任何标准图册的插图 |

### 2.4 边界

| kind | 名称 | 构成要素 |
|---|---|---|
| `inlet` | 进水 | 方框 + 指向下游的箭头 |
| `outlet` | 出水 / 排放 | 方框 + 指向外侧的箭头 |
| `sludgeOut` | 污泥外运 | 方框 + 三条斜线 |

**可开闭性**（流径分析用，见 §5）：`WATER_VALVE_KINDS = ['valve', 'motorValve', 'gate', 'weirGate']` ——
闸门 / 堰门关到底同样断流。**拍门与止回阀不在其中**：它们靠水流方向自动开闭，是单向件，不参与人为开闭。

**在线分析仪的功能代号**（`state.analyzerCode`）：给排水图纸上的仪表本就画成"圆圈 + 功能字母"，
所以在线仪表不按仪表种类拆图元，而是**一种画法 + 可配代号**。字典见 `WATER_ANALYZER_CODES`：
`DO` 溶解氧 / `TU` 浊度 / `CL` 余氯 / `pH` / `ML` 污泥浓度 / `AN` 氨氮 / `COD` / `ORP` / `TP` 总磷 /
`TN` 总氮（不配代号时画 `A`，与旧快照一致）。位号（`tag`，例如 `AIT-101`）照旧显示在符号上方。

## 3. 介质样式（11 种）

给排水图纸靠**颜色与线型**把水线、泥线、空气线、药剂线分开：

| medium | 名称 | 颜色 | 线型 |
|---|---|---|---|
| `sewage` | 污水 | `#475569` | 实线 |
| `effluent` | 出水 | `#0d9488` | 实线 |
| `recycle` | 混合液回流（内回流） | `#0369a1` | 实线 |
| `returnSludge` | 回流污泥（RAS） | `#a16207` | 实线 |
| `sludge` | 剩余污泥（WAS） | `#92400e` | 实线 |
| `air` | 空气 | `#0891b2` | 虚线 |
| `chemical` | 药剂 | `#7c3aed` | 虚线 |
| `signal` | 仪表信号 | `#9333ea` | 点划线 |
| `power` | 动力回路 | `#b45309` | 点划线 |
| `backwash` | 反冲洗水 | `#0e7490` | 实线 |
| `reclaimed` | 中水回用 | `#4d7c0f` | 实线 |

**回流污泥与剩余污泥是两条不同的线**（一个回工艺、一个去处理），所以是两个介质、两个色阶。
**信号线与动力线不是管道**（没有管径、不标 DN）：它们是仪表与电气回路，点划线画出来才能解释
"仪表装在哪、变频器控的是哪台设备"。**反冲洗水与中水都是水流**（实线），与内回流的深蓝、出水的青色分色区分。

## 4. 工艺校验（`validateWater()`）

| 规则 | 级别 | 判据 | 为什么要有 |
|---|---|---|---|
| `duplicate-tag` | error | 位号重复 | 位号是图纸与自控、与现场之间的主键 |
| `isolated-symbol` | warning | 符号没有任何管线 | 漏画连接线是初稿最常见的问题 |
| `pipe-missing-medium` | warning | 管线没标介质 | 分不清水线 / 泥线 / 空气线 |
| `pipe-missing-dn` | warning | 管线没标管径 | 施工图审查的高频缺项 |
| `flow-disconnected` | error | 从进水走不到出水 | 主流程没接通或阀门全关 |
| `outlet-without-analyzer` | error | 出水路径上没有在线水质分析仪 | 排污许可要求在线监测并与生态环境部门联网 |
| `sludge-without-disposal` | warning | 有剩余污泥排出，但没有浓缩 / 脱水 / 外运 | 污泥没有出路 |
| `aao-missing-recycle` | warning | 有好氧池与缺氧池，但缺混合液内回流 | AAO 的工艺合理性提示 |

规则集本身不区分"用哪种图元表达断点"：把闸门 / 堰门画在主流上并置为关闭态，
`flow-disconnected` 会像关阀一样报出断点位置（见 §5）。

## 5. 流径分析（`traceFlow()`）

从进水（`inlet`）沿管线做广度优先搜索到出水（`outlet`），**关断的阀门 / 闸门 / 堰门不通行**
（判据是 `WATER_VALVE_KINDS`；拍门与止回阀是单向件，不参与开闭），
返回 `{ connected, path, outletId, blockedAt }`。

用途：**运行工况推演** —— 「把这条超越管的阀门关上之后，全厂还通不通？」
相当于电力一次图的「带电分析」，是同一套拓扑求解机制在水务场景的对应物。

## 6. 已知限制与待校核清单（诚实交代）

本包的符号与规则是**按标准与行业通行画法自绘的**，以下几处必须由行业专家或设计院校核后才算最终口径：

1. **介质配色与线型是本包的约定**，用于图内自洽与可读性；各设计院院标不同（有的用线型区分、有的用标注区分），
   正式出图前请按项目院标覆盖；
2. **工艺单元画法只表达可辨识特征**（例如沉砂池的集砂斗、二沉池的刮泥桥、闸门的启闭螺杆、巴氏槽的喉部），
   不是逐条对照标准图例的复刻；闸门 / 堰门 / 拍门属启闭类构筑物，**与管道阀门的画法分属两类**，
   只有在"能不能断流"这个拓扑含义上等价；
3. **文字符号（P / B / V / FIT / AIT 等）是行业习惯**，给排水不像电力有 GB/T 7159 那样强制的文字符号体系，
   各院编制规则不同，可自由覆盖；在线分析仪的**功能代号**（`DO` / `TU` / `CL` …）同理 ——
   本包给的是字典与默认画法，不是强制代号体系；
4. **AAO 内回流、污泥出路这类校验是"工艺合理性提示"**，不是设计规范判定；
5. **不含水力计算**（管径选择、水力平衡、泵扬程）——那属于专业水力软件（如供热/给排水水力计算软件）的职责，
   本包只保证"图上的连接关系与标注是对的"。

## 7. 与下游的关系

同一座厂有两张同源的图：**设计态的施工图**（本包）与**运行态的 SCADA 组态画面**。
两者的主键都是"位号"：图纸上的 `AIT-101` 必须与现场仪表、与 SCADA 点表一致。
本包把位号、介质、管径都做成**结构化字段**，正是为了让下游（点表导出、组态骨架、一致性校核）能直接消费，
而不是再照着图纸人工画一遍。
